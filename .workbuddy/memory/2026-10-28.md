# 2026-10-28

## 核心运营逻辑：无 ASIN = 自动断货（Sold Out）

用户要求把「缺少 ASIN」和「断货」自动绑定：某「颜色|尺码」没有 ASIN 就视为断货，
红人无法选择，避免无效选款。

### 关键架构约束
- 前台**匿名红人拿不到真实 ASIN**（`asins` 表 RLS 白名单，且前端故意不请求）。
  唯一的「有没有 ASIN」信号是 `product_links` 公开视图的 `linked_variants`
  （supabase/04 里 `json_object_agg` 所有 `value<>''` 的键）。
- `soldOut.js` 是纯函数（Node 测试套件用），不能 import Supabase/asinStore。

### 实现
- `utils/soldOut.js`：给 `isSoldOut` / `isOptionAvailable` / `soldOutSummary` 加
  **可选参数 `asinLookup`**（`(colour,size)=>boolean` 谓词）。传入时「无 ASIN」与
  `soldOutVariants` 合并判为不可用；不传则只按断货标记（Node 套件零改动）。
  新增内部 `comboUnavailable`。注意 `isSoldOut` 原来 `if(!keys.size) return false`
  的早退必须删掉，否则无断货标记但有 asinLookup 时短路。
- `store/linkStore.js`：新增 `getLinksStatus()` 和 `listingKnownFor(productId,colour,size)`。
  后者在 `status !== 'ready'` 时返回 `true`（链接视图没加载完时假设有 listing），
  避免加载窗口内全站变灰；就绪后才回落 `hasListingFor`。
- 前台接线（都用 `listingKnownFor`，不是裸 `hasListingFor`）：
  - `ProductDetail.jsx`：`asinLookup` → `soldOutNow`、`isOptionAvailable`、已选行 `isSoldOut`。
    无 ASIN 的尺码自动置灰 `(Sold out)`；「No listing linked」软提示改为 `!soldOutNow` 才显示
    （否则与 Sold out 重复）。
  - `ProductCard.jsx`：`soldOutSummary(product, asinLookup)`，全变体无 ASIN → `orderable=false`，
    心形/「Choose options」禁用并显示 `Sold out`。卡片 import `listingKnownFor`。
  - `SelectionPage.jsx`：加 `storefrontSoldOut` 包装，生成码拦截 / 移除断货 都改用它。
  - `CartDrawer.jsx`：`soldOutKeys` 的 `isSoldOut` 注入 `listingKnownFor`。
- 后台 `ProductEditor.jsx` `AsinSection`：`missing>0` 时加红色提示
  「缺少 ASIN 的组合在前台会被当作『Sold Out』处理，红人将无法选择」（中文，配合后台全中文）。
  `ProductsPage.jsx` 的 `! 缺 N` 角标 title 也补了「前台会视为断货」。
- 导入 `src/utils/asinsImportCore.js`：`readTable(rows, { allowMissingAsin=false })`。
  默认不变（空 ASIN 仍 reject）；`batch-upsert.mjs` 传 `true`，空 ASIN 行保留
  （`asin:''`）——颜色/尺码进 specs（前台可见该变体），但不写 asins 键。
  `batch-upsert.mjs` 里 `asinBySku` 剥掉空 ASIN 键喂给 asins 写入，并打印
  「无 ASIN 的变体 N —— 保留 specs、不写 asins（前台视为 Sold Out）」。
  纯 ASIN 导入（import-asins / 浏览器）保持严格模式不变。

### 测试
- `test-sold-out.mjs` 加 `[8] No ASIN = Sold Out` 13 条（89 全过）。
- `test-asins-import.mjs` 加 allowMissingAsin 用例（124 全过）。
- `npm test` 全绿（含 admin-i18n「前台零汉字」红线 + 后台全中文红线）。
- `npm run build` 通过。
- **坑**：后台提示文案若写英文原文会被 `test-admin-i18n` 的「后台漏翻」拦截——
  后台必须全中文，英文那句话只能落在注释或转成中文。

### 遗留提示
- 需求3 的「数据层标记」其实不需要新增字段：asins 表里**没有该键**本身就是标记，
  前端经 `product_links.linked_variants` 判定。导入脚本已天然满足（空 ASIN 不写键）。

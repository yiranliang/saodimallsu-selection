## 修「保存商品后排序被打回原样」（HANDOVER §18）

- 结论：保存不写 `sort_order`（`productToRow` 只在显式传 `sortOrder` 时输出，`updateProduct`
  再 `delete row.sort_order`）。真因是**过期快照覆盖**：一次目录读在拖拽前发出、拖拽后才回来，
  `loadProducts` 的 `inflight` 去重让后续刷新复用它，于是旧顺序一直留在 cache 里。
- 修：`orderEpoch`（本地改顺序 +1；`loadProducts` 读前后比对，不一致就丢弃重读，最多 3 轮；
  `reorderProducts` 乐观更新前 +1、RPC 提交后**再 +1**）；`sortRows()` 客户端按
  `sort_order, id` 排；`updateProduct` / `createProduct` 改用 `resort()`，顺序只从 `orderById` 推导。
- 复现/验证手法：`page.route` 拦 `GET /rest/v1/products`，`route.fetch()` 先取数、压 1.5s 再
  `fulfill`，期间拖一次。关掉守卫 → DOM 停在旧顺序（`P9B031,J7K362,P9B013`）而库里是新顺序；
  打开守卫 → store 丢包重读，DOM 与库一致。
- 新增 `[5k]`：拖拽 → 改另一个商品的名字并保存 → 比数据库 → 比 DOM → 刷新再比；`finally` 还原
  名称与顺序。`test-mapping` 加两条断言：product 上带 `sortOrder`/`sort_order` 也不会写出该列。
- 统计：`npm test` 628、`smoke` 84、`smoke:gate` 113、`asins` 22、`realtime` 11、`soldout` 13、`cart` 35。

## 改颜色/尺码名 = 迁移 variant key（HANDOVER §20，红线 12）

- 背景：导入时颜色是中文（`藏青色`），想改成 `Navy`。`asins.variants` 的键是
  `variantKey(colour,size)` 的**文本**，原来编辑器按完整键查表 → 改名后整行 `Missing ASIN`，
  旧键掉进 extras。数据没丢，但看上去像丢了（用户若顺手清 extras 就真丢）。
- 新增 `src/utils/variantRename.js`（纯函数）：`renamePairs` / `planVariantRenames` /
  `rekeyVariants`（返回 `{variants, renamed, collisions}`）/ `rekeyKeys`（数组版）/ `renamedKey`。
- **判断守卫（关键）**：只有「旧值在新列表里彻底消失」且「新值不在旧列表出现过」才算改名。
  所以 `[藏青色,Red] → [Navy,Red]` = 改名；`[藏青色,Red] → [Red,Navy]`（删旧的+末尾加新的）**不算**。

- 编辑器顺序：`baseAsins` → `rekeyVariants` → 再叠 `asinEdits`（edits 的键已经是新名）。
  顺序反了会制造假 collision。

  否则「改个名 = 悄悄补货」。
- 碰撞策略：目标键已存在时旧键原样保留并记录，不静默丢 ASIN（旧键会出现在 extras）。
- UI：ASIN 面板新增黄色提示 `Renamed A → B — N ASINs follow the new name…`；

## 拖拽颜色图换主图（HANDOVER §25）

- 颜色卡片整块可拖（`draggable` 在卡片根上），拖到左上主图预览框松手 → `patch('image', url)` +
  toast `Main image updated from {颜色} variant`。掉在别处**完全无反应**。
- **载荷用私有 MIME `application/x-influencer-variant-image`，刻意不带 `text/plain`**：
  否则掉在颜色名字输入框上会把 URL 当颜色名插进去——能干净保存，但会污染所有 ASIN 键。
  `test-variant-drop.mjs` 专门断言 types 里没有 text/plain、text/html、text/uri-list。
- `dragover` 时只有 `dataTransfer.types` 可读（载荷读不到），所以放置区在这里决定亮不亮：
  `isVariantDrag(types)` 为真才 preventDefault + 亮描边 + "Drop to use as main image"。
  从桌面拖文件进来根本不亮。
- 三种结局在纯函数 `planMainImageDrop`：`apply` / `noop`（拖的就是当前主图，仍给 toast，
  否则"点了没反应"像按钮坏了）/ `empty`（该颜色没图）。
- 卡片右上角加了 `↑` 按钮 = 同一个 `useVariantAsMain`，**触屏唯一入口**（HTML5 DnD 在触屏上不存在）。
- 新文件 `src/utils/variantDrop.js`；改 `ProductEditor.jsx`、`test-variant-drop.mjs`(27)、`smoke-gate.mjs`(+`[5r]`)。
- **Playwright 模拟 HTML5 拖拽**：`dragAndDrop` 走鼠标事件，Chrome 对 DnD 忽略合成鼠标事件。
  必须 `dispatchEvent('dragstart'|'dragover'|'drop', { dataTransfer })`，dataTransfer 用
  `page.evaluateHandle(() => new DataTransfer())` 真对象。
- 踩的两个定位坑：货号输入框没有 aria-label（是 `placeholder="AMZ-1003"`）；
  页面里有 2 个 `[role="status"]`（工具栏计数 + toast），`innerText()` 会因严格模式报错，
  要用 `.filter({ hasText })`。
- 结果：`npm test` 921 ✓、`smoke:gate` 238 ✓、build ✓（其余套件 84/22/11/35/13 全 ✓）。

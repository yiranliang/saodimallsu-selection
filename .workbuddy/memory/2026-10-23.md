## 选码 v7：索引版 + base62（强制全量）

- 格式：`zby-7.{ref}.{ids}.{radix}.{specs}.{qty}.{ts}.{fp}`，**纯文本不再 base64**（base64 无法含点号，所以「载荷里有 `.` 就是 v7」）。
- ids 四种模式（首字母 + 补零宽度一位）：`r` 区间 / `b` 位图 / `s` 序列（同款多行）/ `t` 字面。编码器 r、b 各算一遍取短。
- specs：每行取「颜色×尺码」网格序号，整列按**全局 radix** 压成一个 BigInt 再 base62。radix 存在码里（不是解码时重算），所以删/改一个商品只影响那一行，后面的行照常解 —— `[21]` 专测这点。
- 哨兵：`digit === comboCount` 表示「这行没选规格」，否则一件式/空规格会被解成第一个颜色。
- 指纹 4 位（选项列表 FNV-1a）：解码重算，不一致 → `optionsChanged` + 后台黄条 + 行内 `请核对颜色尺码`；序号越界则不猜颜色（`variantUncertain`）。
- 已下架：`已下架商品（id）` + 数量，specs 无法还原（序号需要选项列表）。
- 实测（线上 270 在售）：4 款 47、**50 款 138**、70 款 157（v6 分别为 ~100 / 1004 / 1414）。
- 坑：位图最初用字节数组拼 BigInt，**端序写反**导致 id 全错；改成 `bits |= 1n << BigInt(n)`。
- 测试：`npm test` **1117** 条全过；`test-sizes [7]` 的「调序后两码逐字节相同」是 v4 性质，已改为「码不同 + 解码被标记待核对」；`npm run build` ✓。线上只读查询一次，无残留。

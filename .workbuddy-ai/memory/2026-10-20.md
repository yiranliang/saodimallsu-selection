# 2026-10-20

## 红人专属选款网站（MAKO Selection）

从零搭建完成，React 18 + Vite 5 + Tailwind 3，纯前端零后端，位于工作区根目录。

**关键设计决策**

- 路由用 HashRouter（`/#/` 前台、`/#/admin` 后台），部署到任意静态托管刷新都不会 404，无需 `_redirects` 配置。
- 选款码必须「自包含」：红人手机生成、运营电脑查询，中间无服务器，因此不能依赖 localStorage 映射表。格式 `MAKO-{base64url(payload)}`，payload 为 `1.{ref}.{items位掩码base36}.{specs}.{ts秒base36}`。3~5 款约 40 字符，全选 16 款约 92 字符。README 里说明了想要 6 位短码必须上 Workers+KV。
- 位掩码解码用 `Math.floor(mask / 2**i) % 2` 而非 `(mask >> i) & 1`，避开 JS 32 位有符号位运算在 31 个以上商品时的溢出。
- 商品图改为本地生成的 SVG 线稿占位图（`public/placeholders/`，`scripts/gen-placeholders.mjs` 生成），弃用 Unsplash 外链 —— 原因：外链图和商品名对不上、弱网加载慢、有外部依赖风险。
- 卡片上快速点「选款」时自动补齐每个规格类型的第一个选项（`ensureDefaultSpecs`），保证后台拿到的选款单一定带颜色/尺码。
- Toast 同一时刻只保留最新一条，避免连续点选时堆叠遮挡头部。

**踩过的坑**

- 数据里 specs 混用字符串与数组（`颜色: '浅蓝'`），导致编码时漏掉该规格 → 统一改为数组，并在 `code.js` 加 `normalizeOptions()` 兜底。
- admin 子目录组件 import 写成 `./icons.jsx`，实际应为 `../icons.jsx`。

**自检**：`npm run test:code`（14 项断言，纯 Node）。构建产物 gzip 约 64KB。

**待办/边界**：无登录鉴权、每款固定 1 件、商品上限 32 个、商品顺序敏感（选款码存索引）。

## 第二轮改造：英文化 + 多件数量 + 商品编辑器 + 开发者取数

**需求**：① 全站英文；② 开发者能通过专属码拿到所选商品；③ 选款支持每款多件；④ 可视化编辑商品图片/尺码/颜色。

**架构变更**

- 新增 `src/store/productStore.js`：商品库的唯一运行时来源，localStorage 覆盖 `data/products.js` 默认值，`useSyncExternalStore` 订阅。**必须让卡片、详情、编解码器读同一份商品列表**，否则编码和解码会用不同商品库。Node 环境下用 `typeof localStorage !== 'undefined'` 守卫，CLI 脚本才能跑。
- 选款码升级 v2：payload `2.{ref}.{items}.{specs}.{qty}.{ts}`，qty 为每款一个 base36 字符（1–35，与 items 同序）。v1（无 qty 段）仍可解码，数量默认 1。
- `decodeCode()` 返回值从 `null`/对象 改为统一 `{ok:true,...}` / `{ok:false,error}`，不抛异常，方便被外部代码调用。
- 选款状态从 `string[]` 改为 `{[productId]: qty}`；新增 `QuantityStepper` 组件，卡片用 sm、详情弹层用 lg。
- 后台拆成三个路由页签：`/admin`（Lookup）、`/admin/products`（商品编辑器）、`/admin/developer`（JSON）。

**开发者取数三条通道**（都走同一个 `decodeCode`）

1. `window.MAKO.decode(code)` / `.encode()` / `.products()`，在 `main.jsx` 挂载
2. `node scripts/decode.mjs <code> [--json|--table]`，退出码 0/1/2，可管道
3. 后台 Developer 页，格式化 JSON + 复制/下载

**商品编辑器要点**

- 图片支持 URL 或本地上传（FileReader → base64 data URL），单张限 1.5MB，因为 localStorage 只有约 5MB，UI 实时显示占用 KB。正式环境建议用图片 URL。
- 规格编辑用数组形态 `[{type, options[]}]` 保持顺序稳定，保存时丢掉空组/空选项。
- 提供 Export JSON / Copy as products.js / Restore shipped catalogue，形成「浏览器里调 → 固化回 data/products.js」的闭环。
- 顺序敏感警告做成了常驻黄色提示条（码存位置不存 id）。

**测试**：`npm run test:code` 扩到 25 项断言，覆盖多件数量、数量上限钳制、全量商品、非法输入、v1 向后兼容、标识清洗。

**验证方式**：playwright-core + 本机已有 chromium-1223（`executablePath` 直连，绕开版本匹配），跑完整流程：选款→改规格→生成码→后台查询→Developer JSON→改商品价格→前台确认生效，全部通过。临时脚本放 `C:/Users/zby/.workbuddy-ai/tmp-shot`（项目外），用完删除。

**已知边界**：后台无鉴权、商品上限 32、每款上限 35、商品顺序敏感、上传图仅存本机。

- 移除了原来的 `ensureDefaultSpecs` 自动补默认值逻辑。原因写在 README：默认值对红人是隐形的，运营收到错款才发现。

**购物车预览**

**栏目导航**

- 新增 `CategoryNav`，横向 chips，带每类数量，sticky top-0。
- 顺序按 `categories` 数组的规范顺序排（不是字母序，也不是商品插入序），未知分类排最后。

## 第五轮：货号 / ASIN 批量导入 + 选款码 v3

### 需求变更（用户中途修正，覆盖了第一版方案）

最初方案是「id 直接用货号」，用户改回：**id 保留 p001 这类内部标识**，货号存 `sku`。这实际上更干净：

- 货号里的空格、斜杠不用被改写成 id，也就没有「清洗后撞 id」的问题
- 改货号不会让已发出的选款码失效（码里存 id）
- ASIN 按 `sku` 映射，不按 id

### 选款码 v3（核心决策）

载荷 `3.{ref}.{ids}.{specs}.{qty}.{names}.{ts}`，7 段。

- **存 id 不存数组位置**：v1/v2 的位掩码方案在调顺序/删商品后会**静默指错**，这是最危险的一类 bug。v3 彻底解耦。
- **规格存字面值不存选项索引**：改选项名不会失效；商品被删了规格仍然可读。
- **names 段是名称快照**，仅在 `name !== id` 时写入，全部同名时整段为 `_`。用于商品已删除时还能显示「她选的是什么」。
- **转义**：分隔符 `. ~ , =` 和 `%` 走百分号转义（`encodeURIComponent` + 额外转 `.` 和 `~`），中文安全。
- **解码容错**：找不到 id → `missing: true`，保留 id/qty/specs/名称快照，仍计入总数，整码不失败。v1/v2 → `legacy: true` + 黄色提示。
- **长度代价**：3–6 款约 120–220 字符（v2 是 37）。要 6 位短码只能上后端。

### 导入脚本 `scripts/build-catalog.mjs`

`npm run catalog -- sheet.csv`，一次生成三个文件：`data/products.js`、`data/asins.js`、`public/import.js`。

关键实现点（都踩过）：

- **id 复用**：重复导入时按 `sku` 匹配上一版，沿用原 id。否则重新导入会让历史码全部失效。
- **`usedIds` 只在「上一版有 sku」时才填充**。第一次导入时旧目录是 p001–p016 的演示数据，若无条件把它们的 id 算作已占用，新商品会从 p017 起跳。
- **货号重复 → 停下报错**，列出行号，不合并。`--merge-rows` 才合并（颜色/尺码并集，ASIN 拼接去重）。
- **颜色按逗号拆，尺寸额外认 `/`**。因为 `Cream/Tan` 是一个颜色，而 `S/M/L` 是三个尺码。这个不对称是刻意的。
- **尺寸列空 → 整个不生成 `Size`**，前台按 one size 处理。
- **重复导入保留 name/category/image/tag**（后台改过的值），颜色尺码以表格为准。`--fresh` 才全重置。
- 生成代码用 `function` 声明而非 `const` 箭头 —— 模块顶层会立刻调用 `fromDelimited()`，`const` 会 TDZ 报错。

### ASIN 的双层读取

`src/utils/asinStore.js`：localStorage（`mako_asins_v1`）优先，否则 `data/asins.js`。原因：浏览器控制台脚本只能写 localStorage，有了这层覆盖，import.js 导入后 ASIN 立刻可搜索，不用重新部署。

### 踩的坑

- **`normalizeProduct` 是白名单**，只保留 id/name/category/image/tag/specs。加 `sku` 字段时必须同步改这里，否则导入的货号会被静默丢掉。
- **hash 路由下 `page.goto` 到相同 URL 是 no-op**。冒烟测试里从 `#/admin/products` 再 goto 同一地址，React 状态不会重置（上一步的搜索词还在），必须用 `page.reload()`。
- **后台 Toast 用 `top-4` 会盖住页签栏**，改成 `position="bottom"`。
- **商品列表标题**：有 sku 时显示 sku（mono）+ id + name（仅当 name≠sku）；无 sku 时显示 name + id。否则演示数据会出现「p002 p002」重复两行。
- 规格摘要和 ASIN 数量挤在一行会被截断成 "C. 2 ASIN"，改成两行。

### 验证

- `npm run test:code`：56 项断言（含调顺序、删商品、货号/ASIN 解析、分隔符与中文转义）
- `node scripts/smoke.mjs`：15 项浏览器断言（含删商品后查询显示 Removed）
- build 通过，gzip 73.8 KB

### 仍待用户提供

表格文件路径。桌面只有 `~$xxx.xlsx` 锁文件，真实文件在别处。拿到后一条 `npm run catalog --` 即可。

## 第六轮：AOYSKY-SKU.csv 正式导入

### 数据实况（与最初假设不同）

`AOYSKY-SKU.csv` 4,530 行 / 139 个货号，**一行一个 ASIN 变体**（不是一行一个货号），每个货号 5–65 行。表头 `货号,ASIN,颜色,尺寸`，无引号、无内嵌逗号、每行 4 列、BOM 开头。

所以必须用 `--merge-rows`。合并后：139 商品 / 1–13 色（均 6.3）/ 4–7 码（均 5.4）/ 5–65 个 ASIN（均 32.6）。

### 两处主动判断（都留了回退开关）

1. **尺寸排序**：首次出现顺序会得到 `S, XS, XL, XXL, M, L`（因为表按 ASIN 排），明显不可用。用户确认改为常规顺序。默认开启，`--no-sort-sizes` 可关。
2. **尺寸写法统一**：7 个商品同时有 `XXL` 和 `2XL` —— 查原始行确认是两批 ASIN 的写法不一致（老批次 `B0HBB…` 用 XXL，新批次 `B0HMB…` 用 2XL），不是两个尺码。统一为 `XXL`。`--keep-size-spellings` 可关。

### 遗留结构性问题（已告知用户，未擅自改）

- **ASIN 是按货号挂的，不是按「颜色+尺寸」**。运营拿到「P9B051 / Black / XXL」无法直接定位到具体 ASIN。数据里 (货号,颜色,尺寸) → ASIN 基本唯一（4,509 组合中仅 21 处重复），所以如果要做，可以扩成变体表。
- **规格组互相独立**，合并后颜色×尺码是笛卡尔积，前台可能选到表格里不存在的搭配。

### 踩的坑

- 重复货号报告原来会打印每行行号，4,530 行时直接刷屏。改成摘要（行数/货号数/最大行数 + 最重的 5 个），并提示「这种形状通常是一行一个变体，加 --merge-rows」。
- 冒烟测试写死了 `16 products`、`Shoes`、`Charcoal / L`，换数据后全挂。改成从 `products` 里推导期望值（最小分类、首选项组合），并把 `products[0]/[5]` 换成 `A`/`B` 常量。
- 重新导入时 `ids 139 reused` —— id 复用生效，历史码不受影响。

### 验证

test:code 56 项、smoke 17 项（新增「按货号搜索」「货号显示」）、build 通过（gzip 103 KB，因为内联了 139 商品 + 4,529 ASIN）。

## 第六轮：ASIN 变体表 + 选款码去名称快照（v4）

### 用户反馈的两个问题

1. `asins.js` 是 `{ 货号: [ASIN...] }`，后台只显示一堆 ASIN，无法定位红人选的那个变体。
2. v3 码里塞了 URL 编码的商品名称快照，太长。

### 处理

**问题 1 — 改成变体表**

`asins.js` → `{ 货号: { '颜色|尺寸': ASIN } }`。21 处重复组合先列出给用户确认，规则选定「只取第一个，丢弃另一个」（其中 1 处是同 ASIN 的真重复，20 处是不同 ASIN 的真冲突，集中在 8 个货号、两批 ASIN 系列，像是同一款重复上架）。导入器现在保留每行 `entries: [{line, asins, colours, sizes}]`，按 `颜色|尺寸` 建变体表，first-wins，冲突列进报告。

多值单元格（一行里写了多个颜色或多个尺寸）无法归属到具体变体，记进 `unattributed` 并排除出变体表。

**问题 2 — v4**

载荷从 7 段降到 6 段：`4.{ref}.{ids}.{specs}.{qty}.{ts}`。名称快照整段删除。

规格段也顺手压缩：原来每款写 `Colour=Black,Size=M`（重复 12 字符/款），现在只写值 `Black|M`，按商品自己声明的规格类型顺序对应。**这是本轮唯一超出用户字面要求的改动**，但用户明确要求「长度应该明显缩短」，只删名称段只短 18%，删类型名后到 48%。

代价：已删商品的规格键名退化成 `Option 1`/`Option 2`（值还在、顺序还在）。已在 README 和测试注释里写清楚。

### 兼容

`decodeIdBased(parts, {version, hasNames})` 同时处理 v3（7 段，忽略快照）和 v4（6 段）。`parseSpecGroup` 看到 `=` 就走显式键值对解析，否则按位置对应 —— 这样早期 v4 码也还能读。

### 验证数据

- `test:code` 77 项（新增 v3 兼容、单变体 ASIN、无匹配组合、v4 比 v3 至少短 30%）
- `smoke.mjs` 18 项（新增「变体 ASIN 显示」）
- build 通过

真实样例（4 款 7 件，108 字符，v3 同款 209）：
```
MAKO-NC5sdW5hLnAwMDF-cDAwOH5wMDI0fnAwNDIuQmxhY2t8U35OYXZ5JTIwQmx1ZXxMfktoYWtpfFhMfldoaXRlfFMuMjEzMS50bjdhM24
payload 4.luna.p001~p008~p024~p042.Black|S~Navy%20Blue|L~Khaki|XL~White|S.2131.tn7a36
```
后台：P9B013 / Black / S / ×2 / B0H6XHHZ8N 等 4 行全中。

### 踩的坑

- `P9B013` 的 `Black|M` 在表里确实不存在 → 后台显示「No ASIN for this colour / size」，不是 bug。
- 商品名当前还等于货号，后台行标题和副行都显示货号，看起来像重复。加了 `title = name === sku ? sku : name` 和 `showSku = sku !== name`。
- 位置化规格后，`specs` 键名依赖 `Object.keys(product.specs)` 的顺序，值数量必须对齐 —— 编码时按类型逐位占位（未选的留空串），不能跳位拼接。

## 第七轮：按颜色显示变体图（variantImages）+ 编辑器只收 URL

### 数据结构

商品新增可选字段 `variantImages: { [规格类型]: { [选项值]: URL } }`，例如
`{ Colour: { Black: 'https://…/black.jpg' } }`。用「类型 → 值」两层而不是只按颜色，是为了以后能扩到 Size 等其他轴。

### 关键实现

- `src/utils/variantImage.js`（纯函数，Node 也能用）：`variantImageFor` / `resolveProductImage` / `normalizeVariantImages` / `isColourType`。查找时**颜色排最前**，精确匹配失败再忽略大小写匹配。
- `src/components/ProductImage.jsx`：维护 `[变体图, 主图, 占位图]` 链，`onError` 逐级下降。**注意**：`{...rest}` 必须在内部 onError 之前展开，否则调用方传的 onError 会覆盖掉回退逻辑（踩过一次）。
- 卡片、详情弹层、购物车、后台查询结果共用 `resolveProductImage`，避免各处不一致。
- `productStore.normalizeProduct` 的白名单加了 `variantImages` —— 不加就会被静默丢掉，这是持久化的关键点。
- `code.js` 解码时 `image: resolveProductImage(product, specs)`，后台缩略图直接是所选颜色那张。

### 编辑器

- 删掉上传入口（file input / Upload 按钮 / FileReader / base64 提示），只留 URL 输入。
- Colour 组渲染成逐行：缩略图（实时预览）+ 颜色名 + 图片 URL 输入框；其他规格组仍是紧凑 chip。

## 第九轮 · 分类可管理

### 为什么分类要单独一层

原来 `categories` 是 `data/products.js` 里的冻结数组。商品数据可以固化进版本库，但分类是运营随时要调的，跟着一起固化意味着改个分类名就得重新部署。所以拆出 `src/utils/categoryStore.js` + `src/hooks/useCategories.js`，用和商品库完全一样的 localStorage 覆盖 + `useSyncExternalStore` 模式，key 是 `mako_categories_v1`。

### 三处关键逻辑

1. 前台栏目顺序跟随管理清单，商品上出现清单外的分类也显示（排在最后，`Uncategorised` 再往后）。
2. **改名连带改商品**：先 `setProducts` 把商品挪过去，再 `renameCategory`，顺序不能反。
3. **改名撞名合并**：`normalize()` 去重时大小写不敏感，改名到已存在的名字等于合并。
4. `Uncategorised` 是兜底桶：下面还有商品时拒绝删除。

### 编辑器 UI 位置

- 顶部可折叠 `Categories` 面板：每行一个可编辑输入框（`aria-label="Rename <name>"`）+ 商品数 + 垃圾桶（行内二次确认）；底部 `New category` 输入框 + Add。
- 商品弹层里 Category 是 `<input list="category-suggestions">` + `<datalist>`，可挑可手打。
- `handleCopyJS` 在 `export const products` 之前先输出 `export const categories`，顺序即面板顺序。
- 另加 `Copy as asins.js`。

## 第十轮 · 后台访问门禁

### 结构

- `src/config/adminAccess.js` —— 唯一改口令的地方（`ADMIN_PASSCODE = 'Mako2026!'`）+ `SESSION_KEY`。注释里写明「改完必须 build + 部署」。
- `src/utils/adminSession.js` —— `isUnlocked / unlock / lock / subscribe / getSnapshot`，`useSyncExternalStore` 那一套，和 productStore / categoryStore 同风格。sessionStorage 不可用时退回模块级 `memory` 变量（Node 测试也靠这个跑）。
- `src/hooks/useAdminSession.js` —— 订阅通行证。
- `src/components/admin/AccessGate.jsx` —— 导出 `AdminGate`（守门）+ `AccessGate`（锁屏 UI）。
- `src/App.jsx` 把 `<AdminGate><AdminLayout/></AdminGate>` 挂在 `/admin` **父路由**上，所有子路由自动覆盖。
- 新增 `src/pages/admin/AdminNotFound.jsx` + `path="*"`：否则 `/admin/xxx` 在 React Router v6 下整条分支不匹配，页面直接白屏，门禁也没东西可包。

### 关键设计

1. **锁着时 children 根本不渲染**（`if (!unlocked) return <AccessGate />`），不是遮罩。遮罩会在首帧/慢网络时透出内容。
2. **存的是摘要不是口令**：FNV-1a(`salt:passcode`) → 8 位 hex。截图 DevTools 拿不到口令；改口令自动作废所有已登录标签页。
3. sessionStorage 而非 localStorage：关标签页即失效，共用电脑不留后门。
4. 输错 → 红色 `role="alert"` + 输入框清空 + `animate-shake`（tailwind 新增 keyframe）+ 不写 storage。

### 踩的坑

- 第一版在组件里写了 `require('../hooks/useAdminSession.js')` —— Vite/ESM 没有 require，会直接炸。改成顶层 import。
- placeholder 用了 `••••••••`，视觉上像已经填了 8 个字符，输错清空后容易误判。改成 `Enter passcode`。
- React Router v6：父路由带 children 时，URL 不匹配任何 child 就整条不匹配 → 白屏。必须有 `path="*"` 兜底。

### 测试

- `scripts/test-gate.mjs` 31 项（Node，走 memory 回退路径）
- `scripts/smoke-gate.mjs` 36 项（浏览器，含「锁着时 DOM 里没有后台节点」）
- `scripts/unlock.mjs` 共享 helper：从 `src/config/adminAccess.js` 读口令，改口令不会破坏测试
- 三个既有 smoke 脚本各加一次 `unlockAdmin(page)`（sessionStorage 同标签页有效，一次就够）
- 合计 286 项：Node 182（77+28+46+31）+ 浏览器 104（18+19+31+36）

### Cloudflare 那个坑（要记住）

**Cloudflare 看不到 `#` 后面的内容。** HashRouter 下 `/#/admin` 和 `/#/` 对边缘是同一个 `GET /`，所以 Access **没法只保护 `/#/admin`**。要真正防护必须先把后台放到真实路径或独立子域：
- 方案 A（推荐）：后台单独 Pages 项目 + `admin.域名.com` + Zero Trust Access（Self-hosted / One-time PIN，免费 50 用户）。主域那份构建要 `VITE_ADMIN !== '1'` 时剔除 admin 路由，否则主域 `/#/admin` 仍能用口令进。
- 方案 B：改 BrowserRouter 真路径 + `functions/admin/_middleware.js` Basic Auth。
- 方案 C：数据挪到 Worker API（products/asins），保护数据而不只是界面。
